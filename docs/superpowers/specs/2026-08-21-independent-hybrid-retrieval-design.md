# 独立混合检索设计

## 目标

将当前“向量候选集内词项增强”替换为独立的向量检索和关键词检索双路召回。两路结果通过 RRF 融合后统一重排，并保留现有按 `parent_id` 恢复连续记录的能力。

## 范围

- 向量检索继续使用 Milvus HNSW/IP 索引。
- 关键词检索使用本地 SQLite FTS5 持久化索引。
- 新入库的有效子块同时写入 Milvus 和关键词索引。
- 提供显式运维命令，从 Milvus 全量重建关键词索引以覆盖历史数据。
- 保持 `source`、JSON `metadata` 过滤能力和现有 API 合约。

不引入 Elasticsearch、OpenSearch 或特定领域词典。

## 数据模型

关键词索引以每个可检索子块为一条记录，保存以下数据：

- `text`：子块文本，用于 FTS5 全文匹配。
- `source`、`section`、`document_id`、`parent_id`、`chunk_index`、`chunk_count`、`metadata`：用于过滤、融合、重排和连续记录恢复。

索引文件放置在项目可配置的数据目录。SQLite 使用临时文件构建新索引，构建成功后原子替换正式索引文件，避免重建过程留下半成品索引。

## 通用分词

关键词索引和查询统一使用领域无关分词：英文、数字和下划线连续串作为词元；连续中文文本生成二元词，单字单独保留。词元用空格拼接后写入 FTS5，避免依赖特定领域的分词词典。

## 入库流程

1. `chunker.py` 生成带稳定记录元数据的子块。
2. `vector_store.py` 校验 Milvus 固定字段长度，得到有效子块集合。
3. 有效子块先写入 Milvus，再写入关键词索引。
4. 任一写入失败时记录明确错误；关键词索引失败不得伪装为已完成混合索引写入。

关键词索引写入使用子块的稳定键：`document_id`、`parent_id` 和 `chunk_index`。重复写入相同子块时替换旧记录，确保重新入库不产生关键词结果重复。

## 查询流程

```text
查询和过滤条件
  ├─ Milvus 向量召回 Top 40
  └─ SQLite FTS5 关键词召回 Top 40
             ↓
按 parent_id + chunk_index 去重
             ↓
RRF 融合两路排名
             ↓
Reranker 重排融合候选
             ↓
按 source + section 保留最高分命中
             ↓
按 parent_id 查询并排序全部子块
```

两条召回路径必须独立执行。关键词路径不能以 Milvus 向量结果为输入。RRF 使用排名而不是原始分数，避免 IP 相似度、FTS5 BM25 分数和模型重排分数的量纲不一致。

关键词路径应应用与向量路径一致的 `source` 和 JSON `metadata` 过滤。为空或无法形成有效 FTS5 查询的用户查询返回空关键词候选，不影响向量路径。

## 历史索引重建

新增 `scripts/rebuild_bm25_index.py`。脚本连接 Milvus，分页读取完整子块字段，写入临时 SQLite 索引；记录数与错误数输出到标准输出。全部分页成功后以原子替换发布索引；失败时保留旧索引。

运维人员在部署包含此功能的版本后执行一次该命令，使历史文档进入独立关键词检索路径。后续上传由正常入库流程增量维护索引。

## 测试

- 关键词索引可持久化写入、按稳定键更新和按过滤条件查询。
- 关键词召回可返回未出现在向量候选中的精确匹配子块。
- RRF 对两路候选去重并根据两路排名排序。
- 查询在关键词索引为空、查询没有有效词元或关键词路径异常时仍保留向量检索结果。
- 历史重建从分页 Milvus 记录生成完整索引，失败时不替换旧索引。
- 连续记录恢复仍按命中子块的 `parent_id` 获取全部子块并按 `chunk_index` 返回。
