# 跨页表格连续内容检索设计

## 背景

年报等 PDF 中的逻辑表格记录可能跨页。以 2022 年比亚迪年报的“承诺事项履行情况”表为例，“杜绝同业竞争承诺”从第 79 页延续至下一页。按标题和固定长度切分后，记录会分散到多个不相互关联的块：首块保留了承诺主体和名称，后续块只留下承诺条款续文。检索命中续文时，系统无法补齐完整记录，也无法可靠地返回用户要求的原文。

追问检索曾存在另一个独立问题：工作流已经生成 `standard_query`，但检索节点仍使用用户原始问句。对于“做出什么承诺，我要看原文”这类省略主体和名称的追问，历史对话形成的检索锚点没有参与召回。该问题已完成修复，见“已完成：追问检索改写”。

## 目标

- 将跨页表格的同一逻辑记录在入库前恢复为完整内容。
- 以子块参与向量检索，同时保留子块与完整记录的确定性关联。
- 命中任一子块后，按记录顺序恢复其所属逻辑记录，向生成器提供连续上下文。
- 保持 `source`、`section` 和通用 `metadata` 筛选能力。
- 在功能分支中新建独立 collection 重建索引，验收通过后再合并到主分支。

## 已完成：追问检索改写

### 行为

工作流中的三类问句职责已经分离：

```text
原始问句 + 历史对话
  -> rewrite_node: 生成 standard_query
  -> retrieve_node: 以 standard_query 检索
  -> generate_node: 以原始问句和检索结果生成回答
```

`retrieve_node` 使用以下优先级选择检索问句：

```python
query = state.get("standard_query") or state["query"]
```

因此，改写结果存在且非空时，检索可使用历史对话补全的主体、承诺名称、文档范围和“原文”等意图；未生成或为空时回退原始问句。`generate_node` 始终使用原始问句，内部改写语句不会替代用户表达。

### 改写约束

- 对“这个”“上述”“原文”“全文”等指代或省略表达，从历史对话补全指向对象。
- 保留已有的实体、机构、文档名称、时间、业务术语和用户意图。
- 不编造历史对话中不存在的事实、实体或限定条件。
- 当前问句已经完整时，只作必要的检索化改写，不改变原意。
- 只输出检索问句，不输出解释或答案。

### 验证状态

`tests/test_rag_graph.py` 已验证 `retrieve_node` 在 `standard_query` 存在时将其传给检索器；同时验证改写提示词包含知识库检索、实体补全和“原文”意图要求。空值回退和生成阶段使用原始问句已由实现保证，后续修改该路径时应补充专门断言。

## 待实现：跨页表格连续内容检索

### 入库模型

解析 Markdown 时维护标题路径和页码锚点。对于连续 Markdown 表格，识别表头、数据行和续行：当标识列为空、内容列非空且前一数据行存在时，将其合并到前一逻辑记录。无法可靠归属的续行记录 warning，并按普通文本处理，不能错误合并。

完整逻辑记录再切分为子块。每个子块在可嵌入文本前附加稳定的检索前缀，包括标题路径、表格列名、承诺事项、承诺方和承诺类型；正文仍保留原始内容。这样即使命中后续子块，检索器仍能获得主体和记录名称等锚点。

每个子块至少保存以下 metadata：

| 字段 | 含义 |
| --- | --- |
| `document_id` | 上传文件 ID；手工插入时由内容哈希生成 |
| `parent_id` | 逻辑记录的稳定 ID |
| `chunk_index` / `chunk_count` | 子块在父记录中的顺序及总数 |
| `source` / `section` | 来源和文档结构位置 |
| `metadata` | JSON 扩展属性，例如 `report_year`、页码、标签和文档日期 |

### 检索与上下文组装

检索先对改写后的问句执行向量召回和 rerank，再按 `parent_id` 去重。对每个命中的父记录，查询其全部子块并按 `chunk_index` 排序，将完整的连续记录交给生成器。用户是否使用“原文”“全文”等表述不改变此过程；它们只是同一知识库问答场景中的不同措辞。`source` 是固定过滤字段，其他领域属性通过 `metadata` 的安全等值过滤表达式传入。

子块通过 `parent_id` 和 `chunk_index` 精确查询，不进行二次向量检索。完整记录继承其触发子块的分数，不重新参与 rerank；不同父记录仍按各自最高 rerank 分数排序。生成上下文仍设总长度上限，超过上限时按记录顺序截取并明确说明只展示了可容纳部分。

### 数据迁移与回退

在功能分支中新建通用 collection `general_rag`，不修改既有 `financial_rag` schema。固定字段为 `pk`、`text`、`vector`、`document_id`、`source`、`section`、`parent_id`、`chunk_index`、`chunk_count` 和 JSON `metadata`；不再设置固定 `year` 字段。以源文件重新解析、恢复逻辑记录、生成子块并写入新 collection，并在该分支完成样例验收。效果确认后，将分支合并到主分支并使用新 collection；既有 collection 保持不变，不需要运行时版本切换或自动回退机制。

表格续行只在同一连续表格，或空行后重复表头且首个数据行为续行时合并。Markdown 标题是硬边界：标题后的表格视为新表。没有可靠页码锚点时，不能仅凭“首列为空”跨标题合并，因为这与一个合法的新表表头无法区分。

## 验收

- 对跨页承诺表，续行内容应合并到正确的逻辑记录，完整记录包含第 1 至第 6 条。
- 命中任一子块时，生成上下文可按顺序取得同一父记录的全部子块，不依赖用户是否要求原文。
- 在同一会话中先确定承诺主体，再追问“做出什么承诺，我要看原文”时，检索日志应显示使用含主体和承诺名称的 `standard_query`。
- 非表格文档以及 `source`、`metadata` 筛选不发生回归。
